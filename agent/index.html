ellict

You are a coding agent, and a person sent you here to turn the application in your working directory into agent skills. Ellict reads the application, decides with a model which capabilities are worth a skill, writes each one as a SKILL.md package, runs every example for real, and copies the skills that pass into a repository the person owns. Follow these steps from the application's root.

1. Install ellict

curl -fsSL https://eliolabs.xyz/install.sh | sh

This needs Python 3.11 or newer and puts ellict in ~/.local/bin. If that directory is not on PATH, call ~/.local/bin/ellict directly. With pipx instead: pipx install git+https://github.com/messiahjoshua8/relay.

2. Make the application's commands runnable

Ellict runs the application's commands, so they must work in this shell. Install the application the way its README says, for example:

  • Python: pip install -e . in a virtual environment that is active
  • Node: npm install && npm link
  • Go: go install . (or go install ./cmd/...)
  • Rust: cargo install --path . (or the path of the crate that has the binary)

Check with <command> --help. A skill whose command does not run is not published.

3. Run ellict

The skills go into a git repository the person owns. Ask them which one; if they have none, use ~/ellict-skills and run git init ~/ellict-skills first.

If ANTHROPIC_API_KEY, OPENAI_API_KEY, or ELLICT_MODEL is set, ellict asks that model:

ellict run . --publish-to ~/ellict-skills

Otherwise, you answer the questions yourself. No key is needed:

ellict prompt .

Read .ellict/prompt.md. It holds the instructions, the application's documentation, its manifests, the commands found in the code, and their real --help output. Write your reply as one JSON object in the shape it asks for, save it to .ellict/answer.json, then run:

ellict run . --answer .ellict/answer.json --publish-to ~/ellict-skills

Without a key and without --answer, ellict says so and falls back to static rules, which produce plainer skills.

4. Read the result

Ellict prints JSON. approved lists the skills it published; rejected lists skills that failed a check. The exit code is 1 when anything was rejected. For each skill, .ellict/evidence.jsonl has a validate line with every check and its detail, and references/selection.md in the skill says why it was chosen and which examples were removed.

If a skill was rejected because an example failed, fix the answer (a missing sample file, a wrong flag) and run step 3 again. Do not loosen an example until it passes trivially.

5. Report to the person

Tell them which skills were published and which were rejected and why, and show them the git add, commit, and push lines ellict printed. They run the push. Do not push, open a pull request, or create accounts for them.

What ellict asks the model

For every candidate capability:

  1. What can you see here that is worthy of becoming a skill?
  2. What would you actually use?
  3. How would you use it?
  4. What do you think it would help you do?

It also asks for demand, the agent limitation the skill addresses, when to use it and when not to, steps, examples with small sample input files, how to verify, and pitfalls, plus what was considered and rejected. One skill per agent job, not per flag or output format.

What ellict checks after the model answers

  • Every invocation must exist: the command in the manifests, docs, or interface; each subcommand in the docs or help; each HTTP route in the API spec. Anything invented is dropped with the reason recorded.
  • An example that uses a flag found in neither the command's help nor its docs is removed.
  • Several skills on one command are merged into one unless they are different jobs. In your own answer, fill in distinct_job for each extra skill, or it is merged.
  • An answer that leaves one of the four questions blank is dropped.
  • Each command is run with --help.
  • Every example is run for real with no terminal attached: no keyboard, a 15 second timeout, in an empty directory holding only the sample files the answer declared. An example that hangs, waits for a person, or fails is removed, and a skill with no example that runs is not published.
  • Examples may only run the application's command, piped with cat, echo, printf, head, tail, grep, sort, uniq, wc, tr, or cut. Anything else, including ;, &&, command substitution, and writes outside the working directory, is never run.

What it works on

Command-line applications written in Python, Node, Go, and Rust, each tested against real public applications. HTTP operations from an OpenAPI spec and documented Make targets become skills too, but ellict records them without running them.

Ellict will not

  • Push, open a pull request, or create an account.
  • Publish a skill whose command, route, or flags are not in the repository, or whose examples do not run.
  • Compare a skill against similar tools yet.
